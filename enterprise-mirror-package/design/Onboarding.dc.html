Onboard an agent

Six steps. Nothing about the agent's own code changes.
    2.

How does the agent connect?

The agent signs in with the username and password it is issued, as a person would. Only screenshots and actions go to its model.
Reduced guarantees. A remote agent keeps its own internet access, so a leak can be detected but not blocked, and it may see different hostnames than in production. Every report on this agent will say so.

Where does its model run?

The agent is given a placeholder key. The real one is added at the gateway and never enters the sandbox.

Who does it act as?

What will be created
An account and access token in Code hosting, and an account and token in Team chat, both in this person's name. They are issued in the same form production uses.

How does work reach it?

Work always arrives through a system, the way it would for an employee: an assigned issue or a chat message. This step sets how the agent notices.
